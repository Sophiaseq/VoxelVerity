# 体素世界 — 问题抽象与难点

> 目标：UE5 中实现可生成、可破坏的无限体素世界 —— 1/8 体素、相邻面合并成曲面、流式 + 程序化生成、方块模板 + 加工放置。

## 1. 抽象关系

完整关系见 `未命名绘图.drawio`。核心概念链：

- **生成**：`基础层（seed, chunk坐标 → 体素，确定性）` + `编辑层（稀疏 diff）` ⟶ `Voxel = 基础层 ⊕ 编辑层`；`Streaming` 按需加载/卸载 `Chunk`。
- **存储**：`World → Chunk → Voxel → Material`。
- **表现**：`Block Template → Block → Surface Reconstruction → Surface → Mesh → LOD`。
- **玩法**：`Edit → 编辑层`；`体素 →(原料)→ 加工 →(放置)→ Block`；`Tool →(获取)→ Block`（后期桥接 GAS/物品）。

## 3. 风险与难点（按风险降序）

1. **曲面重建正确性与性能** — 标量场提取（surface nets / dual contouring 具体算法未定）是核心难点：邻域查询、边界接缝、材质间过渡。**这是整个项目成败的地基。**
2. **局部重网格化实时性** — 编辑一次 = 改体素 → 重网格化 → 更新碰撞，必须在单帧预算内完成局部（而非全 chunk）重建。
3. **LOD 无缝过渡** — transvoxel 跨 chunk 边界的多分辨率过渡，是"无限 + 1/8 体素"能否跑起来的关键，也是公认的硬骨头。
4. **确定性生成正确性** — 无限流式要求"同 seed 同坐标永远同体素"，需避免浮点/哈希/线程顺序引入不确定性，否则编辑层叠加会错位。
5. **存储/内存** — 1/8 体素 ×512；chunk 尺寸（约 16 方块 = 128 体素/轴）需实测调整，内存成瓶颈再换稀疏八叉树。
6. **UE5 渲染接入** — 动态可变网格在 UE5 的落地路径未定：自定义 `FPrimitiveSceneProxy` vs `ProceduralMeshComponent` vs RuntimeMesh 插件 vs Nanite（Nanite 对动态拓扑不利）。
7. **线程模型** — 生成/重网格化必须后台异步，避免主线程卡顿；需与 UE 的 task graph 结合。
8. **纹理质量** — triplanar 在平滑曲面上的接缝/拉伸需要调试；材质间过渡（blend）是额外难点。
